# 聪明格 KenKen · 算术笼里的行列推理

`N×N` 的盘上，每一行、每一列都是 `1..N` 的一个排列；盘被划成若干「笼」，每只笼左上角写着
「目标数 + 运算符」——笼里那几格用这个运算符（任意次序）必须算出目标数。这里出货的每一盘都只有
一个答案，也每一盘都能用四条局部推理从空盘一路推到底——一次都不许靠猜。

本文里的数字只有两类来源：仓里读得到的代码（写成 `文件:行号`），和 2026-09-28 那次全绿跑出来的
读数。跑的命令是 `npm run check`、`node tools/engine-test.mjs`、`SAMPLES=24 node tools/balance.mjs`、
`node tools/bake.mjs --check`、`bash tools/verify.sh`，环境 Node v26.8.1 / macOS。引擎断言、`npm run
check`、`bake --check` 是当场重跑的；难度分位表与浏览器门禁的读数是那次全绿会话的输出，逐条列在下面。

**代码 > 本文档**：本文与 `js/`、`tools/` 冲突时，以代码和它跑出来的输出为准。

## 规则（玩家视角）

两类事实，四条规则。规则原文就是菜单里那段列表（`index.html:63-70`）：

1. **行列排除**：同行同列已有的数字互相挤候选；一个数字在一行里只剩一格放得下，就得填在那里。
2. **极值与边界**：一个笼的和/积有可达区间。目标数出界就矛盾；某个一填就出界的候选，不能在这格。
3. **笼组合枚举**：把这个笼在 `1..N` 内所有算得通的组合列出来取交集——一个组合里都没有的数字全部
   排除，所有组合都落在同一格的数字直接填上。
4. **笼与行列装箱**：一行里各个笼贡献的数字之和必须是 `N(N+1)/2`。配不满就矛盾，只剩一种配法就
   把那一格钉死。

- 四条都只看局部事实，所以它们写下的每一格、每一处排除在盘面的**每一个解**里都成立
  （`index.html:70` 那句 `rules-note`，代码侧的根据是 `js/engine/kenken.js:1-12`：`solve()` 是一条
  **绝不回溯**的铅笔路径）。
- 判胜不另起口径：`complete()`（`js/engine/kenken.js:925-927`）就是"`verify()` 一条问题都没有"且
  "一格不落都填了"。`verify()`（`js/engine/kenken.js:902-923`）只读盘面，自己按行列排列和笼算术逐条查，绝不读引擎
  写下的中间结论——提示逻辑写错，伪造不出一场胜利。
- 运算符只有五种：`=`（单格定值）、`+`、`−`、`×`、`÷`（`js/engine/kenken.js:17-25`）。界面上是数学
  符号，序列化进题面文本的是 ASCII，两者不能混用（`js/engine/kenken.js:26`）。

- 五档：初学 4²、上手 5²、熟练 5²、高阶 6²、大师 7²（`js/engine/generate.js:314-360`），外加按天换题的

  20 关四章的战役目录（`js/data/campaign.js`，烤炉见下文）。

  （`index.html:136`）。铅笔模式下数字键记候选而不是落子；落了子那一格的铅笔自动作废
  （`js/ui/game.js:298`）。
- 「清理铅笔」是给懒人的工具：它只擦掉引擎**已经证明不可能**的候选，不改题面、不占步数
  （`js/ui/game.js:332-346`）。它进撤销栈，所以撤得回来；正因为当初没计费，撤销它也不退步
  （`js/ui/game.js:357`，理由见本文最后两节）。
- 提示是"下一步可证的事实"：说出哪一格必须是什么、凭四条里的哪一条、看的哪个笼，计费一次；
  它不替玩家填格子（`index.html:125`，纪律钉在 `tools/engine-test.mjs` 的「C 状态机 · 提示不是答案」）。
  你自己已经填反了的时候，键盘那条路对盘外数字是「什么都不做」（`js/main.js:582` 的 `v <= size` 闸）。
- 侧栏六个读数（步数 / 提示 / 已落子 / 算对的笼 / 冲突格 / 难度实测，`index.html:115-120`）全部由
  引擎现算，不是界面自己数格子。
- 存档只有一份、一个键 `kenken.save.v1`（`js/store.js:13`）：接着上次那盘继续，墨水与铅笔都是
  游程编码（实测一张 4 阶盘的整份存档 371 字节，`tools/scenarios.js` 的 play 场景量到的）。

## 这个仓**不承诺**什么

- **不承诺「唯一解 ⟹ 铅笔推得完」**。四条规则不完备，反方向不成立：有些只有一个答案的盘，这四条
  就是推不完——那正是生成器要丢掉的东西，不是漏网的答案。`reachable()` 逼不出矛盾只说明没找到反证，
  它从不说"这样放是对的"。
- **不承诺出题耗时**。`tools/balance.mjs` 只把每张的墙钟印在表里（本次实测 0.8 / 1.1 / 1.2 / 1.3 /
  11.7 ms 每档一张），不设 `budgetMs` 门禁；进闸的是确定性的**穷举节点数**：战役目录里最难那关
  264,711 个节点，`tools/scenarios.js:375` 断它必须 `< 600000`，同一次跑里 20 关合计 378,762。
- **不承诺接受率**。裸生成（`tries=1`、不设 band）出货率：初学 21/24、上手 23/24、熟练 15/24、
  高阶 6/24、大师 6/24（SAMPLES=24 实测）。带内率也不是 100%：熟练 87%、大师 83%，另外三档 100%——
  这就是"至少一半样本落进 band"这条闸存在的原因，也是它不放宽到 100% 的原因。
- **不承诺 8 阶以上**。引擎的候选集是 16 位掩码，`MAX_SIZE = 9` 是编码上限（`js/engine/kenken.js:14`），
  但五档出货最大 7²。8、9 阶没有任何一条断言为它们作保。
- **有代码、但浏览器闸没断言过的分支**：菜单上的「音效」「动效」两个开关，闸只把它们当作控件量了
  点击盒尺寸（`tools/scenarios.js:936` 的 `census`），**从没点过它们**，也就没断言过按下之后
  WebAudio 是否真的静音、`prefers-reduced-motion` 那条链路是否真的换了动效档
  （`js/main.js:563-572`、`:680-685`）。
- **只在 headless Chrome 里绿过**。Safari、Firefox、真机 iOS/Android、低配设备未经验证。
  `bash tools/verify.sh` 跑的是本机 root 形态与本机带 `/z-biz-game-kenken-cos/` 前缀的两种 URL
  （两种形态各 324 条，2026-09-28 实测，整轮 17.5 秒）。第三种形态也跑过了——已部署的
  `https://z-biz-game.github.io/z-biz-game-kenken-cos/`，走 `BASE_URL=` 那条路（`tools/verify.sh:164-166`，
  它不起任何本地服务，只连一个 headless Chrome）：同一套 5 个场景、**324 条、0 失败、10.0 秒**
  （2026-09-28 05:4x），而且报出来的读数与本机一致（`worstNodes 264711`、`inkCode 2.0x3.1.0xb`、
  `painted 53188`）。部署件与磁盘的字节也对过：`index.html`、`js/main.js`、`js/engine/kenken.js`、
  `js/render/board.js`、`css/game.css` 五份的 sha256 前 12 位一一相同。仍未验证的是浏览器种类与设备。
- Electron 壳（`electron/main.cjs`）只有 `npm run check` 的 `node --check` 级检查，没有任何运行时断言。

## 难度是量出来的

难度分 = `40×规则等级负担 + 25×重规则占比 + 15×依赖链深度 + 20×盘规模`，四个量各自归一到 0..1
（权重写死在 `js/engine/generate.js:191`，函数 `difficulty()` 在 `:194`）。

一开始用的是「铅笔结论条数 × 规则权重」的原始分，80 张一批跑下来把它否了：这个分几乎只跟盘的
边长走，同一张 4 阶盘里"满是单格笼的送分题"和"全是三格大笼的硬题"只差 3 分，而且送分题略高——
因为笼子越小、能排除的候选越多、写下的结论条数越多。**拿它当难度就是在量格子数**。所以四项
全部改成跟边长无关的量，只留一个温和的规模项（这段否决过程记在 `js/engine/generate.js:177-190`）。

SAMPLES=24 的实测分位表（2026-09-28，`node tools/balance.mjs` 的 stdout）：

|---|:---|:---|:---|:---|:---|:---|:---|
| 初学 | 4² | 21/24 | 26..40 | 28.1 | 31.5 | 37.5 | 100% |

"重规则占比"= 需要规则③（笼组合枚举）或规则④（笼与行列装箱）的结论占比，这四条里最贵的两条；
四档的权重分别是 1 / 2 / 2.5 / 3.5（`js/engine/kenken.js:401-431`）。

## 四条规则与那道算术（引擎视角）

| 规则 | 权重 | 只读什么 |
|---|---|---|
| ① 行列排除 | 1 | 一行、一列 |
| ② 极值与边界 | 2 | 一只笼的和/积可达区间 |
| ③ 笼组合枚举 | 2.5 | 一只笼在 `1..N` 内的全部合法组合 |
| ④ 笼与行列装箱 | 3.5 | 一行（一列）里所有笼的贡献之和 vs `N(N+1)/2` |

规则③的赋值枚举有硬预算：`ASSIGN_BUDGET = 3000`（`js/engine/kenken.js:434`）。引擎还留了两个只供
测试的旋钮（`js/engine/kenken.js:535-540` 注释写的 `rules` / `budget`），用来实测"规则②到底是③的
简化版还是兜底版"——这条口径由 `tools/engine-test.mjs` 的「A 规则可靠 · 四条规则的分工（谁也不是
挂饰）」18 条钉着。

## 文档行号对账（`node tools/docs-test.mjs`）

本文与 `DESIGN.md` 里印着一百多条 `path:行号`（其中一大半是只写行号的续引），写那句话的时候
没有任何机器核过它们。这一闸把根目录下每一份 `.md` 读进来，把反引号里的引用逐条开回文件对账：

```
$ node tools/docs-test.mjs
  · 解析 117 条 · 续引 10 条 · 无法定址 0 处 · 带指认 35 条 · 跨仓引用 0 处

文档行号对账：2 份文档 · 117 条引用 · 35 条带指认 · 28 条判据

28 通过 / 0 失败
```

这条腿自己发 28 条判据（台账：文档行号对账 28 条）——上面那个数由它本轮实发，删掉一条断言就撞红。

- 边界：文件必须在盘上、行号必须落在真实行数内，而且**被指的那几行不许整段是空行**——
  「在界内」不等于「指到了代码」。
- 锚点：贴着引用写的那个名字（`name`（`path:NN`）、`path:NN`（`name`）、`path:NN` 的 `name`、
  `path:NN`（`fn(a, b)`）等六种贴法都认）必须作为**完整标识符**出现在被指的那几行里。子串不算：
  短名字坐在声明长标识符的那一行上也会"出现"，子串口径会把一次真的漂移读成绿。
- 续引：`tools/verify.sh:24`、`:27` 这种只写行号的，向同一句里最近那条完整引用借路径；句号、分号、
  空行、新标题都截断这次借，借不到的计入「无法定址 0 处」——不判错，也不静默跳过。
- 它对自己的口径也下刀：跨仓引用与本地假路径一对（前者按形状分出去、只数不判，后者照旧红）、
  七条续引控制腿、九把假引用全被抓到、以及"把文档里一条真引用的行号挪歪一格，这条腿必须为它变红"。
  这些靶子全部现量（符号名从声明行里读、空行行号从空白扫描里读、前缀靶子从"子串命中而整词不命中"的
  真声明里挑），没有写死的行号——写死行号的夹具会在有人往那个文件上面插一行的那天停止测试。
- 接线：同一条命令住在 `npm test` 的链里、`bash tools/verify.sh` 的末尾与 CI 的 check job 里
  （`.github/workflows/ci.yml` 里真有 `run: node tools/docs-test.mjs`，认的是调用那一行）。
  它**不在**引擎测试那批文件里——`node tools/engine-test.mjs` 的 655 条是引擎断言，别把两个数混着抄。

## 技术形态

- 运行时零依赖：引擎、UI、渲染、存档全是手写 ES module，浏览器直接 `<script type="module">` 加载，
  没有构建步骤。`package.json` 的 devDependencies 只有 Electron 一个，而且 CI 里**没有
  `npm install`**——为了让 CI"什么也不证明"而把 Electron 拉进容器，就是让仓库从此开始怕网络抖动。
- 纯模块不碰 DOM：`js/engine/*.js` 里读不到 `window`、`document`（`js/engine/kenken.js:11-12`），
  同一份文件在 Node 和 Chrome 里跑；跨引擎确定性由 `fingerprint` 场景实测（20 关在浏览器里按同一颗
  种子重烤，题面文本与答案逐格相同：`textSame 20/20`、`answerSame 20/20`）。
- Pages 部署是无构建的文件拷贝（`.github/workflows/pages.yml`）。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高——文件图标读文件头，
  内联成 base64 的图标先解码再读同一段。后一条不是可选项：图标可能住在清单里而不是盘上的 `.png`
  （有的仓另有一条"零二进制文件"的承诺，那条只约束"有没有 .png 这个文件"）；如果 P 段只筛文件名，
  声明写 512 而真图 192 就一路放行。
- **钉住两个数**：R 段实际检查的路径条数（`31`）与这一次跑的断言条数（`49`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字，也不写别仓文档闸的编号：有的仓的文档闸会拿"文档里出现过的同名标识号"回数它
  自己的条数，还有的会把文档里点到的每个组编号逐个核对"这一轮真的发过"——两道闸共用一个名字，
  或者在本仓的文档里出现一个本仓没有的组编号，打红的都是不相干的那一边。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`31`、断言仍然 `49`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug /
X13 内联位图谎报尺寸——只在有靶子时下：X11/X12 要页面上那句 og:image，X13 要清单里真有一段 base64
图标，没有就打印 SKIP；反过来 X1 没有位图目录可砍时改砍 css，P 段一位都不核时台架直接报靶子不够），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；本仓的整闸在 `tools/verify.sh` 的 `=== deploy-set ===` 那一段也各跑一次。它们红的时候并进本仓那条出口的退出码——这一条是这么证的：
把 ci.yml 里那行 `run: node tools/deploy-set.mjs` 砍掉，本仓整闸必须点名红且退出码非 0。
所以「本地全绿、线上 404 自己的 manifest / sw.js / 图标」这一类坏法在本地就会红。
